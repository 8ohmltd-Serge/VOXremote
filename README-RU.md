# VOXORDIA Remote Gateway

Портал `connect.voxordia.com` является общей точкой входа для удалённых
участников разных установок VOX-S. Он не показывает список заказчиков,
серверов или конференций. Пользователь вводит персональный десятизначный код,
после чего портал направляет только управляющие HTTP/SSE-запросы через
исходящий WSS-туннель нужного VOX-S.

Аудио и видео через портал не проходят. Браузер устанавливает WebRTC-соединение
напрямую с публичным IPv4 заказчика и указанным на VOX-S диапазоном UDP.

## Требования

- контейнерная площадка или VPS с HTTPS/WSS для `connect.voxordia.com`;
- Node.js 22, если запуск выполняется без Docker;
- PostgreSQL 15 или новее;
- публичный ключ издателя лицензий EDGE-S (только публичная часть PEM);
- сертификат TLS завершается на reverse proxy или платформе размещения.

Локальный Docker и собственный VPS не обязательны. Railway собирает Dockerfile
на своей инфраструктуре и выдаёт тестовый HTTPS-домен автоматически.

Секреты, ключи установок VOX-S и исходный код персональных кодов портал не
хранит. В PostgreSQL сохраняются только SHA-256 кодов и сессий.

## Переменные среды

Задайте переменные в секретах площадки, не добавляя их в репозиторий или образ:

- `DATABASE_URL` — строка подключения PostgreSQL;
- `VENDOR_PUBLIC_KEY_PATH` — путь к смонтированному публичному PEM издателя;
- `VENDOR_PUBLIC_KEY_BASE64` — альтернатива пути: публичный PEM в Base64 для
  платформ без файловых секретов, включая Railway;
- `PORT` — внутренний HTTP-порт, обычно `8080`;
- `TRUST_PROXY=1` — включить только за доверенным reverse proxy;
- `PGSSL=require|disable` — режим TLS к PostgreSQL при необходимости.

## Публикация контейнера

### Railway без локального Docker

1. Подключите отдельный GitHub-репозиторий `VOXremote` к существующему сервису
   Railway. Для этого репозитория Root Directory — `/`; путь
   `/tools/remote-gateway` относился к прежнему монорепозиторию и здесь неверен.
   Сборка и health check уже заданы в `railway.json`.
2. В том же Railway Project добавьте PostgreSQL.
3. В сервисе шлюза задайте `DATABASE_URL` ссылкой на переменную PostgreSQL,
   `TRUST_PROXY=1` и `VENDOR_PUBLIC_KEY_BASE64` с публичным PEM издателя,
   закодированным в Base64. Файл и volume не нужны.
4. Публичный ключ не является секретом, но подменять его через форму или базу
   нельзя. Закрытый ключ издателя в Railway никогда не помещается.
5. Нажмите Generate Domain и испытайте портал на выданном
   `*.up.railway.app`. Railway поддерживает долгоживущие WebSocket-соединения.
6. После приёмки добавьте Custom Domain `connect.voxordia.com`, внесите выданные
   Railway записи CNAME и TXT в DNS. Сертификат выпускается и обновляется
   Railway автоматически.

Локально выполнять `docker build` при этом не требуется.

### Собственный контейнерный хост

1. Создайте PostgreSQL и постоянный секрет-файл с публичным PEM издателя.
2. Соберите образ: `docker build -t voxordia-remote-gateway .`.
3. Запустите контейнер с переменными среды и PEM, смонтированным только для
   чтения в путь из `VENDOR_PUBLIC_KEY_PATH`.
4. Привяжите `connect.voxordia.com` к HTTPS-домену площадки. Она должна
   пропускать WebSocket Upgrade на `/gateway/connect` без отдельного таймаута
   в несколько минут.
5. Проверьте `GET https://connect.voxordia.com/health`: ответ должен содержать
   `ready:true`.
6. В RemoteCore каждого VOX-S укажите публичный IPv4 его медиатракта и
   диапазон UDP. Дополнительный DNS, сертификат и входящий TCP-порт заказчику
   не требуются; нужен исходящий WSS/443 и NAT для медиадиапазона.

Схема PostgreSQL применяется идемпотентно при старте из `schema.sql`.

## Приёмка перед переключением DNS

- неверный, отозванный и просроченный код не создают cookie сессии;
- один код однозначно ведёт к одной установке и участнику;
- переподключение работает до закрытия конференции;
- отключение туннеля возвращает 503 и не раскрывает адрес установки;
- административные маршруты VOX-S через туннель недоступны;
- в браузере проверены камера, микрофон, SSE и повторный вход;
- выбранные ICE candidate pair и сетевые счётчики доказывают прямой путь
  браузер ⇄ VOX-S, без трафика RTP через `connect.voxordia.com`;
- проверены два одновременно подключённых сервера заказчиков.

Текущий лимит одного управляющего запроса через туннель — 2 МиБ. Загрузка
крупных документов удалённым участником пока не входит в приёмку.
